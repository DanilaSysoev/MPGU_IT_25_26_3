# Занятие №13: Поведенческие паттерны. Команда (Command)

**Цель занятия:** Изучить паттерн Command. Научиться инкапсулировать запросы как объекты, реализовать гибкую систему управления (Input Handling) и (опционально) систему отмены действий (Undo).

**Продолжительность:** 180 минут.

Тринадцатое занятие — **Команда (Command)**. Это один из самых "геймплейных" паттернов, потому что он позволяет реализовать две вещи, которые делают игру игрой:

1. **Настройка управления (Input Remapping):** "Хочу прыгать на Пробел, а стрелять на Enter".
2. **Отмена действий (Undo/Redo):** В пошаговых играх это вообще must-have, но даже в реал-тайме это полезно для редактора уровней.

## Часть 1. Теория и Live Coding (90 минут)

### 1. Проблема жесткого Input (15 мин)

* **Контекст:** Обработка клавиатуры в игре.
* **Плохое решение:**

    ```csharp
    void Update() {
        if (Input.GetKeyDown(KeyCode.Space)) Jump();
        if (Input.GetKeyDown(KeyCode.X)) Fire();
    }
    ```

  * *Проблема:* Если игрок захочет поменять кнопку прыжка на `Ctrl`, нам придется лезть в код и перекомпилировать игру. Нельзя поменять управление в меню настроек.

### 2. Паттерн Command (30 мин)

* **Суть:** Превращает запрос (вызов метода) в объект.
* **Метафора:** Заказ в ресторане.
  * Клиент (Invoker) говорит: "Суп!".
  * Официант записывает "Заказ №42: Суп" на бумажку (Command).
  * Бумажка передается на кухню. Повару (Receiver) все равно, кто заказал суп, он просто варит его по бумажке.
* **UML:**
  * `ICommand`: Метод `Execute()`. (Иногда `Undo()`).
  * `ConcreteCommand`: Хранит ссылку на Получателя (`Receiver`) и вызывает его метод.
  * `Invoker`: Инициатор (Кнопка, Клавиатура). Хранит команду и вызывает `Execute()`.
  * `Receiver`: Исполнитель (Герой, Дверь). Знает, *как* выполнить действие.

### 3. Live Coding: Input Handler (45 мин)

* **Задача:** Сделать так, чтобы можно было переназначать кнопки управления.
* **Шаг 1. Интерфейс Команды:**

    ```csharp
    public interface ICommand {
        void Execute();
        void Undo(); // Для отмены
    }
    ```

* **Шаг 2. Конкретные команды:**
  * `JumpCommand`:

    ```csharp
    public class JumpCommand : ICommand {
        private Player _player;
        public JumpCommand(Player p) { _player = p; }
        public void Execute() { _player.Jump(); }
        public void Undo() { /* Логика приземления? */ }
    }
    ```

  * `FireCommand`: `_player.Fire();`.
* **Шаг 3. Обработчик ввода (Invoker):**

    ```csharp
    public class InputHandler {
        // Кнопки привязаны к командам!
        private ICommand _buttonSpace; 
        private ICommand _buttonX;

        // Метод переназначения (Remapping)
        public void BindSpace(ICommand command) { _buttonSpace = command; }

        public void HandleInput() {
            if (Input.GetKeyDown(KeyCode.Space)) _buttonSpace?.Execute();
            if (Input.GetKeyDown(KeyCode.X)) _buttonX?.Execute();
        }
    }
    ```

* **Шаг 4. Использование (Main):**

    ```csharp
    Player player = new Player();
    InputHandler input = new InputHandler();

    // Настройка управления (по умолчанию)
    input.BindSpace(new JumpCommand(player));

    // Игрок зашел в настройки и поменял прыжок на "Ничего"
    input.BindSpace(new NullCommand()); // Паттерн NullObject
    ```

## Часть 2. Практическое задание (Домашняя работа) (90 минут + дом)

**Тема:** Реализация паттерна Команда.

### Задание (На выбор)

#### Вариант А: Input Remapping (Управление)

1. **Создать команды:** Минимум 3 команды для действий персонажа (`MoveCommand`, `AttackCommand`, `UseItemCommand`).
2. **Реализовать Invoker:** Класс `InputManager`, который хранит словарь `Dictionary<ConsoleKey, ICommand>`.
3. **Демонстрация:**
    * В начале игры настроить управление (W -> Move, Space -> Attack).
    * В процессе игры (через меню или консольную команду) переназначить кнопки (W -> Attack, Space -> Move).
    * Проверить, что персонаж начал вести себя по-новому.

#### Вариант Б: Undo System (Отмена действий)

1. **Создать команды:** Для действий, которые меняют состояние мира (`MoveCommand` - меняет координаты, `PickUpCommand` - меняет инвентарь).
2. **Реализовать Undo:** В интерфейс `ICommand` добавить метод `Undo()`.
    * В `MoveCommand.Execute()` запоминать *старые* координаты перед перемещением.
    * В `MoveCommand.Undo()` восстанавливать старые координаты.
3. **Стек истории:** В `GameManager` создать `Stack<ICommand> history`.
    * При выполнении команды класть её в стек.
    * При нажатии `Ctrl+Z` доставать последнюю команду и вызывать `Undo()`.
4. **Unit-тест:**
    * Проверить: Игрок на (0,0) -> Move(1,0) -> Undo() -> Игрок снова на (0,0).
5. **Результат работы влейте в main с коммитом "Task 13 ready."**

**Дедлайн:** 1 неделя.

| **Качество кода** | **1** | Команды названы глаголами или существительными действия (`JumpCommand`), отсутствие дублирования логики в `Execute`. |

### Штрафы

* **Logic inside Command:** `-1 балл`. Если команда содержит сложную бизнес-логику (расчет физики прыжка), а не делегирует её получателю (`_player.Jump()`). Команда должна быть *тонкой*.
* **Нет Undo (для варианта Б):** `-2 балла`. Если выбран вариант с отменой, но метод `Undo` пустой или не работает.
* **Hardcoded Keys:** `-1 балл`. Если в классе Команды проверяется нажатие клавиши (`if (Key == Space)`). Команда не должна знать, *кто* и *как* её вызвал.

### Методический комментарий

* **Сложность Undo:** Самая частая ошибка в Undo — забыть сохранить состояние *перед* изменением.
  * *Совет:* Напомните про паттерн **Memento (Снимок)**, если они начнут сохранять состояние всего мира ради отмены одного шага. Но для учебного примера достаточно хранить пару переменных (`_prevX`, `_prevY`) внутри самой команды.
* **Очередь команд:** Покажите, что Команда может использоваться не только для Input, но и для **AI**. Враг может планировать свои действия: `Queue<ICommand> plan`. Сначала подойти, потом ударить. Это мощная идея.
