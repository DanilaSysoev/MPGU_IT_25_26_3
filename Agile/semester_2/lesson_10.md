# Занятие №10: Поведенческие паттерны. Стратегия (Strategy)

**Цель занятия:** Изучить паттерн Strategy. Научиться выносить семейство алгоритмов в отдельные классы и делать их взаимозаменяемыми, реализуя гибкое поведение игровых объектов (AI или механики).

**Продолжительность:** 180 минут.

---

## Часть 1. Теория и Live Coding (90 минут)

### 1. Проблема жесткого кода (15 мин)

* **Контекст:** У нас есть класс `Enemy`. Мы хотим, чтобы он иногда атаковал в ближнем бою, иногда стрелял из лука, а иногда убегал.
* **Плохое решение (Switch/If-Else):**

    ```csharp
    public void Act() {
        if (type == "Melee") { ... }
        else if (type == "Ranged") { ... }
        else if (health < 10) { ... } // Спагетти-код
    }
    ```

  * *Проблема:* При добавлении нового типа поведения (например, "Лекарь") придется менять класс `Enemy`, нарушая OCP. Класс разрастается до нечитаемых размеров.

### 2. Паттерн Strategy (30 мин)

* **Суть:** Определяет семейство алгоритмов, инкапсулирует каждый из них и делает их взаимозаменяемыми.
* **Метафора:** Навигатор.
  * Цель одна: добраться из А в Б.
  * Стратегии разные: На машине, Пешком, На общественном транспорте.
  * Навигатор (Контекст) просто вызывает метод `BuildRoute()`, не зная деталей реализации.
* **UML:**
  * `Context` (Контекст): Класс, использующий стратегию (`Enemy`).
  * `IStrategy` (Интерфейс): Общий метод (`Execute()`).
  * `ConcreteStrategyA`, `ConcreteStrategyB`: Реализации (`AttackStrategy`, `FleeStrategy`).

### 3. Live Coding: Система передвижения (45 мин)

* **Задача:** Реализовать персонажа, который может менять способ перемещения (Ходьба -> Полет -> Плавание).
* **Шаг 1. Интерфейс Стратегии:**

    ```csharp
    public interface IMovementStrategy {
        void Move();
    }
    ```

* **Шаг 2. Конкретные Стратегии:**
  * `WalkStrategy`: `Console.WriteLine("Иду пешком...");`
  * `FlyStrategy`: `Console.WriteLine("Лечу в облаках!");`
  * `SwimStrategy`: `Console.WriteLine("Плыву брассом.");`
* **Шаг 3. Контекст (Герой):**

    ```csharp
    public class Hero {
        private IMovementStrategy _movementStrategy;

        // Внедрение зависимости через конструктор или метод
        public void SetMovementStrategy(IMovementStrategy strategy) {
            _movementStrategy = strategy;
        }

        public void Move() {
            if (_movementStrategy == null) {
                Console.WriteLine("Стою на месте.");
                return;
            }
            _movementStrategy.Move(); // Делегирование
        }
    }
    ```

* **Шаг 4. Использование (Main):**

    ```csharp
    Hero hero = new Hero();
    hero.SetMovementStrategy(new WalkStrategy());
    hero.Move(); // Иду пешком...

    // Смена стратегии на лету!
    hero.SetMovementStrategy(new FlyStrategy());
    hero.Move(); // Лечу!
    ```

## Часть 2. Практическое задание (Домашняя работа) (90 минут + дом)

**Тема:** Реализация сменного поведения (AI или Механики).

### Задание (На выбор)

1. **Создать интерфейс:** Создайте интерфейс для реализации стратегии (например `ICombatStrategy` или `IAttackBehavior`).
2. **Реализовать стратегии:** Реализуйте подходящие вашему проекту стратегии поведения, например:
    * `MeleeAttack`: Подойти к игроку и ударить (вывод в консоль + уменьшение HP).
    * `RangedAttack`: Выстрелить издалека (шанс промаха).
    * `FleeBehavior`: Убежать, если здоровье ниже 20%.
    * `PassiveBehavior`: Просто стоять и ничего не делать.
3. **Интеграция:** В классе контекста добавить поле для стратегии. В игровом цикле (`Update`) вызывать метод стратегии.
4. **Результат работы влейте в main с коммитом "Task 10 ready."**

**Дедлайн:** 1 неделя.

## Критерии оценивания (Максимум 8 баллов)

| Критерий | Баллы | Описание |
| :--- | :---: | :--- |
| **Интерфейс Стратегии** | **1** | Выделен общий интерфейс (например `IStrategy`) для семейства алгоритмов. |
| **Конкретные Стратегии** | **2** | Реализовано минимум 2-3 разных поведения в отдельных классах. |
| **Контекст** | **1** | Класс-контекст (`Enemy` / `Hero`) имеет поле типа интерфейса и метод для его смены (`SetStrategy`). |
| **Смена на лету** | **1** | В игре продемонстрировано переключение поведения без пересоздания объекта (например, враг начал убегать). |
| **Качество кода** | **1** | Понятные имена классов (`AggressiveStrategy`), Git Flow. |
| **Тесты** | **2** | Код покрыт unit-тестами |
| **Итого** | **8** | |

### Штрафы

* **Наследование вместо композиции:** `-3 балла`. Если вместо стратегии студент сделал `class AggressiveEnemy : Enemy`, `class CowardEnemy : Enemy`. Это работает, но это *не паттерн Стратегия*. Задача была именно на смену поведения *одного и того же* объекта.
* **Логика внутри Контекста:** `-1 балл`. Если в методе `ExecuteStrategy` контекста остался кусок логики (`if (health < 10) ...`). Стратегия должна быть самодостаточной (или получать данные через аргументы).
