# Занятие №14: Сохранение данных (Persistency)

**Цель занятия:** Научиться сохранять и загружать состояние игры, используя сериализацию (JSON) и работу с базой данных (PostgreSQL/SQLite) для таблицы рекордов.

**Продолжительность:** 180 минут.

**Методическая цель:**

1. Показать разницу между **Сериализацией** (превращением объектов в байты/строки) и **Сохранением** (записью на диск).
2. Дать выбор инструмента: простой JSON (для настроек) или База Данных (для рекордов/сложного инвентаря).
    * *Важно:* Вы упоминали, что они знают Docker и PostgreSQL. Это отлично, но поднимать полноценную БД ради сохранения координат игрока (X, Y) — это **Overengineering** (избыточная инженерия). Мы должны объяснить, когда нужна БД, а когда нет.

## Часть 1. Теория и Live Coding (90 минут)

### 1. Проблема сохранения (15 мин)

* **Контекст:** Игрок прошел сложный уровень, закрыл игру, открыл — и он снова на старте.
* **Задача:** Сохранить состояние объектов (`Player`, `World`, `Inventory`) на жесткий диск.
* **Сериализация:** Процесс превращения графа объектов в поток байтов (или строку JSON/XML), который можно записать в файл или передать по сети.

### 2. JSON Serialization (Newtonsoft / System.Text.Json) (30 мин)

* **Почему JSON?** Человекочитаемый, простой, поддерживается везде.
* **DTO (Data Transfer Object):**
  * *Проблема:* Нельзя сериализовать весь класс `Player` (там ссылки на `GameManager`, события, текстуры).
  * *Решение:* Создать специальный класс-посредник `PlayerSaveData` (только поля: X, Y, HP, InventoryID).
* **Live Coding:**

    ```csharp
    // DTO
    public class GameSaveData {
        public int PlayerX { get; set; }
        public int PlayerY { get; set; }
        public int Health { get; set; }
        public List<string> InventoryItems { get; set; }
    }

    // Сохранение
    public void SaveGame(Player player) {
        var data = new GameSaveData {
            PlayerX = player.X,
            Health = player.Health,
            // ... маппинг
        };
        string json = JsonSerializer.Serialize(data);
        File.WriteAllText("savegame.json", json);
    }

    // Загрузка
    public void LoadGame() {
        if (!File.Exists("savegame.json")) return;
        string json = File.ReadAllText("savegame.json");
        var data = JsonSerializer.Deserialize<GameSaveData>(json);
        // ... восстановление состояния игрока из data
    }
    ```

### 3. Работа с БД (PostgreSQL / SQLite) (30 мин)

* **Когда нужна БД?**
  * Таблица рекордов (High Scores) — нужно сортировать, выбирать топ-10.
  * ММО (многопользовательская игра) — данные на сервере.
  * Сложная статистика (сколько орков убито за всё время).
* **ORM (Entity Framework Core / Dapper):**
  * Показать *очень кратко*, как подключиться к БД.
  * Показать создание таблицы `HighScores` (Name, Score, Date).
  * Показать `INSERT` и `SELECT TOP 10`.

### 4. Паттерн Repository (15 мин)

* Чтобы отделить логику игры от базы данных, используем **Репозиторий**.
  * `IHighScoreRepository`: Метод `AddScore(name, score)`, `GetTopScores()`.
  * Реализация `FileHighScoreRepository` (пишет в файл).
  * Реализация `SqlHighScoreRepository` (пишет в БД).

### Штрафы

* **Сериализация MonoBehaviour / Logic:** `-2 балла`. Если студент пытается сериализовать весь класс `Player` со всей его логикой, ссылками на текстуры и приватными полями. Это вызовет `Loop Reference Exception` или сохранит мусор.
* **Хардкод путей:** `-1 балл`. Если путь к файлу сохранения `C:\Users\Vasya\...`. Нужно использовать относительные пути или `Environment.GetFolderPath`.
* **Пароли в коде (БД):** `-1 балл`. Если пароль от БД закоммичен в репозиторий. (Должен быть в конфиге/переменных окружения, или хотя бы вынесен в отдельный файл, который в `.gitignore`).

### Методический комментарий

* **Тестирование IO:** Тестировать запись на диск в Unit-тестах — плохая практика (медленно, нужен доступ к диску).
  * *Решение:* Пусть тестируют *преобразование* (Mapper) из `Player` в `PlayerDto` и обратно. Это чистая логика. А сам факт записи файла можно оставить на ручное тестирование или Интеграционные тесты.
* **Почему не BinaryFormatter?** Предупредите, что `BinaryFormatter` в .NET признан **небезопасным** (Obsolete) и его использовать нельзя. Только JSON, XML или Protobuf.
