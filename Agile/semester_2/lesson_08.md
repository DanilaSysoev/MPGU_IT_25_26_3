# Занятие №8: Структурные паттерны (Adapter / Facade)

**Цель занятия:** Изучить паттерны Adapter и Facade. Научиться интегрировать сторонние (или несовместимые) классы в свою систему и упрощать взаимодействие со сложными подсистемами.

**Продолжительность:** 180 минут.

---

## Часть 1. Теория и Live Coding (90 минут)

### 1. Проблема интеграции (Adapter) (20 мин)

* **Контекст:** Вы пишете игру. У вас есть интерфейс `IEnemy`, который ожидает метод `Attack()`.
* **Ситуация:** Вы нашли в интернете крутую библиотеку AI, где есть класс `SuperBot`. Но у него метод называется `SmashPlayer()`.
* **Проблема:** Вы не можете просто так добавить `SuperBot` в свой список `List<IEnemy>`, потому что он не реализует ваш интерфейс. И менять код библиотеки вы не можете (она скомпилирована / чужая).
* **Решение (Адаптер):** Создать класс-прослойку, который *выглядит* как `IEnemy`, а внутри *вызывает* `SuperBot.SmashPlayer()`.

### 2. Live Coding: Адаптер для логгера (35 мин)

* **Задача:** У нас есть свой логгер `ILogger`. Мы хотим подключить стороннюю библиотеку `ThirdPartyLogger`, которая пишет в JSON, но имеет другой интерфейс.
* **Шаг 1. Наш интерфейс:**

    ```csharp
    public interface ILogger {
        void Log(string message);
        void LogError(string message);
    }
    ```

* **Шаг 2. Сторонний класс (Чужой код):**

    ```csharp
    // Представим, что это библиотека из NuGet
    public class ThirdPartyJsonLogger {
        public void WriteJsonLog(string key, string value) { ... }
    }
    ```

* **Шаг 3. Адаптер:**

    ```csharp
    public class JsonLoggerAdapter : ILogger {
        private ThirdPartyJsonLogger _adaptee; // Ссылка на чужака

        public JsonLoggerAdapter(ThirdPartyJsonLogger adaptee) {
            _adaptee = adaptee;
        }

        public void Log(string message) {
            // Адаптируем вызов: наш "message" превращаем в пару "Info": message
            _adaptee.WriteJsonLog("Info", message); 
        }

        public void LogError(string message) {
            _adaptee.WriteJsonLog("Error", message);
        }
    }
    ```

* **Вывод:** Теперь `GameManager` может работать с `JsonLoggerAdapter` как с обычным `ILogger`, не зная, что под капотом сложная JSON-библиотека.

### 3. Проблема сложности (Facade) (15 мин)

* **Контекст:** Запуск игры — это ад. Нужно:
    1. `AudioSystem.Init()`
    2. `VideoSystem.SetResolution(1920, 1080)`
    3. `PhysicsEngine.Start()`
    4. `Network.Connect()`
* **Проблема:** Если каждый раз писать эти 4 строки в `Main`, мы нарушаем принцип DRY и рискуем что-то забыть.
* **Решение (Фасад):** Создать класс `GameEngineFacade` с одним методом `StartGame()`, который сделает всё это внутри себя.

### 4. Live Coding: Фасад системы сохранения (20 мин)

* **Задача:** Упростить процесс сохранения игры.
* **Сложная система (Подсистема):**
  * `FileSaver` (работает с файлами).
  * `DataSerializer` (превращает объект в байты).
  * `CompressionUtils` (сжимает данные).
* **Фасад:**

    ```csharp
    public class SaveSystemFacade {
        private FileSaver _fileSaver = new FileSaver();
        private DataSerializer _serializer = new DataSerializer();
        private CompressionUtils _compressor = new CompressionUtils();

        public void SaveGame(GameState state, string filename) {
            var data = _serializer.Serialize(state); // 1. Сериализация
            var compressed = _compressor.Compress(data); // 2. Сжатие
            _fileSaver.Write(filename, compressed); // 3. Запись
        }
    }
    ```

* **Вывод:** Клиент (Кнопка "Сохранить") вызывает только одну строчку `facade.SaveGame(...)`.

## Часть 2. Практическое задание (Домашняя работа) (90 минут + дом)

**Тема:** Интеграция стороннего API или упрощение сложной логики.

### Задание (На выбор)

#### Вариант А: Адаптер (Рекомендуется, если есть что адаптировать)

1. **Сценарий:** Представьте, что вы хотите заменить какую-то часть своей системы (например, консольный вывод) на другую реализацию, которая имеет *несовместимый* интерфейс.
    * *Пример:* У вас есть интерфейс `IMapGenerator` с методом `Generate()`. Вы нашли класс `DungeonGenerator` (из интернета или написали сами "в стиле другой библиотеки"), у которого метод называется `CreateDungeon(int width, int height)`.
2. **Реализация:**
    * Создайте "несовместимый" класс (Adaptee).
    * Создайте класс-Адаптер, реализующий *ваш* интерфейс.
    * Внутри методов Адаптера вызывайте методы Adaptee, преобразуя данные при необходимости.
3. **Демонстрация:** Подмените в игре старую реализацию на новую (через Адаптер) и убедитесь, что код игры не сломался.

#### Вариант Б: Фасад (Рекомендуется, если система уже сложная)

1. **Сценарий:** У вас есть сложный процесс, который требует вызова нескольких методов из разных классов в определенном порядке.
    * *Примеры:*
        * **Бой:** `CalculateDamage()`, `ApplyArmor()`, `CheckCritical()`, `PlaySound()`, `ShowEffect()`.
        * **Смена уровня:** `UnloadCurrentLevel()`, `ShowLoadingScreen()`, `LoadNewLevel()`, `SpawnPlayer()`.
2. **Реализация:**
    * Создайте класс `BattleFacade` (или `LevelManagerFacade`).
    * Спрячьте всю сложную логику вызовов внутри простого метода (например, `DoTurn()` или `ChangeLevel()`).
3. **Демонстрация:** Замените лапшу кода в основном цикле на вызов метода Фасада.
4. **Результат работы влейте в main с коммитом "Task 8 ready."**

**Дедлайн:** 1 неделя.

### Штрафы

* **Адаптер к себе:** `-2 балла`. Если студент адаптирует свой же класс, который он *мог бы* просто переписать под нужный интерфейс. Адаптер нужен для *чужого* или *legacy* кода.
* **God Object (Фасад):** `-1 балл`. Если Фасад не просто делегирует вызовы, а содержит в себе всю бизнес-логику (считает урон, рисует графику). Фасад должен быть "тонким" дирижером.
* **Наследование (Адаптер):** `-1 балл`. Адаптер объектов (через композицию) предпочтительнее Адаптера классов (через множественное наследование, которого нет в C#, но студенты пытаются имитировать).

### Методический комментарий

* **Разница:** Студенты спросят: *"В чем разница между Фасадом и Декоратором? И там и там обертка."*
  * *Ответ:*
    * **Декоратор** *не меняет интерфейс*, он добавляет функционал. Интерфейс остается тем же (`IWeapon`).
    * **Адаптер** *меняет интерфейс* (подгоняет квадратное под круглое).
    * **Фасад** *создает новый, упрощенный интерфейс* для группы классов.
* **Где взять пример для Адаптера:** Предложите им адаптировать `System.Random` к вашему интерфейсу `IRandomProvider` (если он есть). У `System.Random` есть методы `Next()`, а у вас может быть `GetFloat()`. Это отличный, простой пример.
