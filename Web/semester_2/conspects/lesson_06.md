## Часть 1. Конспект лекции

### 1. Django Shell: Лаборатория разработчика

Зачем нам консоль, если есть админка?

* **Админка:** Для контент-менеджеров (медленно, кликаем мышкой).
* **Shell:** Для программистов (быстро, пишем код, тестируем сложные выборки, меняем 1000 записей одной командой).
* **Запуск:** `python manage.py shell`.
  * *Лайфхак:* Если установить `pip install ipython`, консоль станет цветной и с автодополнением. Рекомендуем!

### 2. Менеджер объектов (`objects`)

У каждой модели есть "Менеджер" — это интерфейс для обращения к таблице.
Синтаксис: `Модель.objects.метод()`.

### 3. Основные методы (CRUD - Read)

* **Create (Создать):**
    `Item.objects.create(name='Coffee', price=100)` — сразу сохраняет в БД.
* **Read (Читать):**
  * `.all()` — Дай мне **ВСЁ**. Возвращает `QuerySet` (умный список).
  * `.filter(price=100)` — Дай мне список тех, у кого цена 100. Возвращает `QuerySet`.
  * `.exclude(price=0)` — Дай всех, кроме бесплатных.
  * `.get(id=1)` — Дай мне **конкретно этот** объект.
    * *Опасно:* Если объекта нет — ошибка `DoesNotExist`. Если их два — ошибка `MultipleObjectsReturned`. Используем только для поиска по уникальным полям (ID, slug).
  * `.first()`, `.last()` — Первый или последний из списка.
* **Update (Обновить):**
  * Получили объект -> изменили поле -> `.save()`.
* **Delete (Удалить):**
  * Получили объект -> `.delete()`.

### 4. Магия лени (Lazy Evaluation)

Django не бежит в базу данных в тот момент, когда вы написали `Item.objects.filter(...)`. Он бежит туда только тогда, когда вы **попросили данные**: вывели на экран, запустили цикл `for` или превратили в `list`. Это экономит ресурсы.

## Часть 2. Практика (Live Coding)

*Преподаватель демонстрирует:*

### Этап 1. Работа в Shell

```python
python manage.py shell

# 1. Импорт модели (обязательно!)
from myapp.models import Product

# 2. Создание объектов
Product.objects.create(title='Ноутбук', price=50000)
Product.objects.create(title='Мышка', price=1000)
Product.objects.create(title='Монитор', price=20000)

# 3. Выборки
items = Product.objects.all()
print(items) # <QuerySet [<Product: Ноутбук>, ...]>

cheap_items = Product.objects.filter(price__lt=5000) # Меньше 5000
print(cheap_items)
```

### Этап 2. Вывод на сайт (Интеграция)

1. Идем в `views.py`.
2. В функции `index_view`:

    ```python
    from .models import Product # Не забываем импорт!

    def index(request):
        # Получаем все товары из БД
        items = Product.objects.all() 
        
        # Кладем их в контекст
        context = {
            'products': items
        }
        return render(request, 'index.html', context)
    ```

3. Идем в `index.html`. Используем цикл:

    ```html
    <div class="row">
        {% for product in products %}
            <div class="col-md-4">
                <div class="card">
                    <div class="card-body">
                        <h5>{{ product.title }}</h5>
                        <p>Цена: {{ product.price }} руб.</p>
                    </div>
                </div>
            </div>
        {% endfor %}
    </div>
    ```

## Часть 3. Домашнее задание №6

**Тема:** Оживление каталога. Вывод данных из БД в шаблон.  
**Срок выполнения:** 1 неделя.  
**Максимальный балл:** 8 баллов.  

### Описание задания

Вам необходимо наполнить вашу базу данных контентом (используя консоль или админку) и вывести этот список на главной странице вашего сайта в виде красивой сетки карточек.

### Техническое задание (ТЗ)

1. **Наполнение данными (Data Seeding):**
    * Запустите `python manage.py shell`.
    * Импортируйте вашу модель.
    * Создайте минимум **5-6 объектов** с разными данными через консоль (используйте команду `.create()`).
    * *Альтернатива:* Можете создать их через админку, но мы рекомендуем потренироваться в консоли.

2. **View (Python):**
    * В `views.py` импортируйте вашу модель.
    * В функции, отвечающей за главную страницу (или страницу каталога), получите все записи: `items = MyModel.objects.all()`.
    * Передайте переменную `items` в словарь контекста (`context`) под понятным ключом (например, `'posts'`, `'goods'`, `'books'`).

3. **Template (HTML + DTL):**
    * Откройте шаблон страницы.
    * Найдите место, где у вас была "рыба" (статичные карточки Bootstrap). Оставьте только **одну** карточку как образец.
    * Оберните эту карточку в цикл `{% for item in items %}` ... `{% endfor %}`.
    * Внутри карточки замените статический текст на переменные объекта:
        * Заголовок: `{{ item.title }}`
        * Описание: `{{ item.description|truncatewords:20 }}` (используйте фильтр для обрезки длинного текста).
        * Цена/Дата: `{{ item.price }}`.

4. **Обработка пустоты:**
    * Используйте тег `{% empty %}` внутри цикла.
    * Если база пуста, выведите красивое сообщение: "К сожалению, товаров пока нет. Заходите позже!".

5. **Результат работы влейте в main с коммитом "Task 6 ready."**

### Критерии оценивания (Аддитивная система)

Максимум: **8 баллов**.

| Критерий | Баллы | Описание |
| :--- | :---: | :--- |
| **View Logic** | **+2** | Во view корректно выполнен импорт модели и запрос `.all()`. Данные переданы в `render`. |
| **Цикл в шаблоне** | **+2** | Использован тег `{% for %}`. Карточки генерируются динамически (сколько записей в БД, столько и на сайте). |
| **Вывод атрибутов** | **+2** | Внутри карточки выводится реальная информация из объекта (Заголовок, Описание и т.д.), а не заглушки "Lorem Ipsum". |
| **Обработка Empty** | **+1** | Реализован блок `{% empty %}` или проверка `{% if items %}` для случая, когда список пуст. |
| **Внешний вид (Bootstrap)** | **+1** | Карточки выстроены в сетку (Grid), не слипаются, выглядит аккуратно. |

### Штрафы

* **-2 балла:** Оставлены статические карточки-дубликаты (код не следует принципу DRY).
* **-1 балл:** Ошибка `NameError` (забыли импортировать модель во `views.py`).
* **-1 балл:** Вывод "сырого" объекта (например, `{{ item }}` вместо `{{ item.title }}`), если метод `__str__` не настроен или не информативен.
