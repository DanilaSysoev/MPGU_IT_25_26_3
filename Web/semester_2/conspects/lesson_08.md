## Часть 1. Конспект лекции

### 1. GET vs POST

* **GET (Дай):** Параметры видны в адресной строке (`?search=cats`). Используется для получения данных. Безопасно для обновления (F5).
* **POST (Возьми):** Данные спрятаны в "теле" запроса. Используется для изменения состояния (отправка пароля, создание поста). При обновлении страницы браузер спрашивает "Отправить данные повторно?".

### 2. Зачем нужен класс `Form`?

Почему не писать просто HTML `<input>`?

1. **Генерация HTML:** Django сам нарисует инпуты.
2. **Валидация:** Django сам проверит: "А ввел ли пользователь email? А число ли это?".
3. **Безопасность:** Очистка данных от SQL-инъекций и XSS.

> **Аналогия:**
> **HTML-форма** — это пустой бланк заявления, лежащий на столе. Вы можете написать там что угодно.
> **Django Form** — это строгий чиновник в окошке. Он берет бланк, проверяет каждую букву, сверяет дату и, если что-то не так, возвращает бланк с красными пометками "Исправьте здесь".

### 3. CSRF (Cross Site Request Forgery)

Это атака "Межсайтовая подделка запроса". Злоумышленник может сделать кнопку на своем сайте, которая скрыто отправит деньги с вашего банка, если вы там залогинены.
**Защита:** Django выдает каждому посетителю секретный токен (`csrf_token`). При отправке формы сервер проверяет: "А это наш токен или поддельный?".
**Правило:** Внутри любой формы `POST` всегда пишем `{% csrf_token %}`.

### 4. Жизненный цикл формы во View

```python
def contact_view(request):
    if request.method == 'POST':
        # 1. Пользователь прислал данные
        form = ContactForm(request.POST)
        # 2. Проверяем валидность
        if form.is_valid():
            # 3. Чистые данные (словарик)
            print(form.cleaned_data)
            # 4. Перенаправляем (чтобы не было повторной отправки)
            return redirect('success_page')
    else:
        # 1. Пользователь просто зашел на страницу (GET)
        form = ContactForm()

    # Рисуем страницу (с ошибками или пустую)
    return render(request, 'contact.html', {'form': form})
```

## Часть 2. Практика (Live Coding)

*Задача: Создать форму обратной связи, которая "принимает" сообщение и выводит его в консоль сервера.*

**Шаг 1. Файл `forms.py`**
Внутри приложения создаем файл `forms.py`.

```python
from django import forms

class ContactForm(forms.Form):
    name = forms.CharField(label='Ваше имя', max_length=100)
    email = forms.EmailField(label='Email')
    message = forms.CharField(label='Сообщение', widget=forms.Textarea)
```

**Шаг 2. View**
В `views.py` пишем логику (см. пункт 4 в лекции). Создаем простую `success_view`.

**Шаг 3. Шаблон**
В `contact.html`:

```html
{% extends 'base.html' %}

{% block content %}
  <h1>Напишите нам</h1>
  
  <form method="post">
    {% csrf_token %}
    
    <!-- Простой способ вывода -->
    {{ form.as_p }}
    
    <button type="submit" class="btn btn-primary">Отправить</button>
  </form>
{% endblock %}
```

**Шаг 4. Стилизация (Bootstrap)**
*Проблема:* `{{ form.as_p }}` выглядит скучно.
*Решение:* Добавляем классы прямо в python-коде (виджеты).

```python
# forms.py
name = forms.CharField(widget=forms.TextInput(attrs={'class': 'form-control'}))
```

### Критерии оценивания (Аддитивная система)

Максимум: **8 баллов**.

| Критерий | Баллы | Описание |
| :--- | :---: | :--- |
| **Класс Form** | **+2** | Файл `forms.py` создан, поля типизированы верно (EmailField проверяет наличие @). |
| **Логика View** | **+2** | Обработан и GET, и POST. Есть проверка `is_valid()`. |
| **CSRF** | **+1** | Токен защиты присутствует в форме. Без него отправка выдаст 403. |
| **Redirect** | **+1** | После успешной отправки страница перезагружается через редирект (паттерн PRG - Post/Redirect/Get). |

* **-1 балл:** Отсутствие перенаправления (после отправки форма просто рендерится заново с введенными данными, и при обновлении браузер спрашивает "Повторить отправку?").
