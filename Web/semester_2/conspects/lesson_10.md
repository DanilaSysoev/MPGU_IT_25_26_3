## Часть 1. Конспект лекции

### 1. Как работает вход на сайт? (Sessions & Cookies)

HTTP — протокол без состояния. Сервер забывает вас сразу после ответа.
Чтобы сервер помнил, что вы — это вы, используется механизм **Сессий**.

1. Вы вводите логин/пароль.
2. Сервер проверяет их в БД (`auth_user`).
3. Если ок — сервер создает в своей таблице сессий (`django_session`) запись и выдает вам **Cookie** (ID сессии).
4. Браузер прикрепляет эту куку к каждому следующему запросу. Django видит куку, находит сессию и понимает: `request.user = admin`.

### 2. Приложение `django.contrib.auth`

Django уже имеет всё необходимое:

* Модель `User` (username, password, email, first_name, last_name).
* Вьюхи: `LoginView`, `LogoutView`.
* Формы: `UserCreationForm` (регистрация), `AuthenticationForm` (вход).

### 3. Разграничение доступа (Permissions)

* **Аноним:** `request.user.is_authenticated == False`. Ему можно только смотреть.
* **Залогинен:** `request.user.is_authenticated == True`. Ему можно создавать.
* **Автор:** Тот, кто создал запись. Ему можно редактировать.
* **Суперюзер:** Ему можно всё.

### 4. Декораторы

Чтобы не писать `if not user.is_authenticated: return redirect(...)` в каждой функции, мы "оборачиваем" функцию в декоратор `@login_required`. Он сам перенаправит на страницу входа, а потом вернет обратно (`?next=/create/`).

## Часть 2. Практика (Live Coding)

*Преподаватель показывает:*

**Шаг 1. Настройка URL для Auth**
В `config/urls.py` (главном):

```python
from django.urls import path, include

urlpatterns = [
    # ...
    # Это подключит готовые маршруты: /accounts/login/, /accounts/logout/ и т.д.
    path('accounts/', include('django.contrib.auth.urls')),
]
```

**Шаг 2. Шаблон входа (`login.html`)**
Django по умолчанию ищет шаблон в папке `registration`.
Создаем: `templates/registration/login.html`.

```html
{% extends 'base.html' %}

{% block content %}
<h2>Вход</h2>
<form method="post">
  {% csrf_token %}
  {{ form.as_p }}
  <button type="submit" class="btn btn-primary">Войти</button>
</form>
{% endblock %}
```

*Настройка:* В `settings.py` добавить `LOGIN_REDIRECT_URL = '/'` (куда кидать после входа) и `LOGOUT_REDIRECT_URL = '/'`.

**Шаг 3. Регистрация (Своя View)**
Тут готовой вьюхи нет, пишем сами.
`users/views.py`:

```python
from django.contrib.auth.forms import UserCreationForm
from django.urls import reverse_lazy
from django.views.generic import CreateView

class RegisterView(CreateView):
    template_name = 'registration/register.html'
    form_class = UserCreationForm
    success_url = reverse_lazy('login') # После регистрации -> на вход
```

Подключаем в `urls.py`.

**Шаг 4. Изменение Модели (Самое сложное!)**
Добавляем автора к товару/посту.
В `models.py`:

```python
from django.contrib.auth.models import User

class Item(models.Model):
    # ... старые поля ...
    # on_delete=models.CASCADE: если удалят юзера, удалятся и его посты
    author = models.ForeignKey(User, on_delete=models.CASCADE, verbose_name='Продавец') 
```

*Миграция:* При `makemigrations` Django спросит: "У вас есть старые записи без автора. Что делать?".
Выбираем вариант **1** (Provide a one-off default), вводим `1` (ID суперюзера).

**Шаг 5. Привязка автора при создании**
В `views.py` (где `create_item`):

```python
@login_required
def create_item(request):
    if request.method == 'POST':
        form = ItemForm(request.POST)
        if form.is_valid():
            item = form.save(commit=False) # Пока не пишем в БД
            item.author = request.user     # Присваиваем автора
            item.save()                    # Теперь пишем
            return redirect(...)
```

## Часть 3. Домашнее задание №10

**Тема:** Реализация системы пользователей.  
**Срок выполнения:** 1 неделя.  
**Максимальный балл:** 8 баллов.  

### Описание задания

Вам необходимо ограничить доступ к функциям изменения сайта. Создавать и редактировать контент могут только зарегистрированные пользователи. Также необходимо реализовать связь "Автор — Объект".

### Техническое задание (ТЗ)

1. **Система входа/выхода:**
    * Подключите `django.contrib.auth.urls`.
    * Создайте шаблон `registration/login.html`.
    * В шапке сайта (`base.html`) добавьте логику:
        * Если пользователь вошел: показывать "Привет, {{ user.username }}" и кнопку "Выход".
        * Если аноним: показывать кнопки "Вход" и "Регистрация".

2. **Регистрация:**
    * Реализуйте возможность регистрации новых пользователей через `UserCreationForm`.
    * Создайте соответствующий шаблон и маршрут `/accounts/register/`.

3. **Изменение модели данных (Migration):**
    * Добавьте поле `author` (ForeignKey на модель `User`) в вашу основную модель.
    * Создайте и примените миграцию. (Для существующих записей назначьте автором суперпользователя).

4. **Защита View:**
    * Добавьте декоратор `@login_required` к функциям создания, редактирования и удаления записей.
    * Анонимные пользователи при попытке зайти по прямой ссылке `/create/` должны перенаправляться на логин.

5. **Автоматическое авторство:**
    * В функции создания записи (`create_view`) измените сохранение формы. Исключите поле `author` из HTML-формы (пользователь не должен выбирать автора из списка).
    * Присвойте `item.author = request.user` в коде (используя `commit=False`).

6. **Результат работы влейте в main с коммитом "Task 10 ready."**

### Критерии оценивания (Аддитивная система)

Максимум: **8 баллов**.

| Критерий | Баллы | Описание |
| :--- | :---: | :--- |
| **Login / Logout** | **+2** | Вход и выход работают. В меню навигации кнопки меняются в зависимости от статуса (`is_authenticated`). |
| **Регистрация** | **+2** | Можно создать нового пользователя, он сохраняется в БД и может войти. |
| **Поле Author** | **+2** | В модели есть связь с User. В базе данных у записей прописан ID создателя. |
| **Защита доступа** | **+1** | Нельзя создать пост без логина (редирект на /login/). |
| **Привязка автора** | **+1** | При создании поста автор подставляется автоматически. В форме нет выпадающего списка "Выберите автора". |

* **-2 балла:** Ошибка миграции (не смогли добавить поле к существующей таблице и удалили базу данных/миграции). Мы учимся решать конфликты, а не удалять данные.
* **-1 балл:** Хардкод ссылок на вход/выход вместо `{% url 'login' %}`.
* **-1 балл:** Отсутствие `csrf_token` в формах входа/регистрации.
