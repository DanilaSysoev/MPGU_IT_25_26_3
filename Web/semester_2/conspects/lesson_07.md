# Урок 7. Детальный просмотр и Динамические URL

**Тип занятия:** Лекция + Live Coding  
**Продолжительность:** 3 астрономических часа  
**Сложность:** Средняя (понимание маршрутизации)  

## Цели урока

1. Понять концепцию **Dynamic URL Routing**: как передавать параметры через адресную строку.
2. Разобраться, что такое `pk` (Primary Key) и `id`.
3. Использовать шорткат `get_object_or_404` для безопасного получения данных.
4. Создать страницу детального просмотра (Detail View).
5. Связать страницу списка и страницу товара ссылкой.
6. *(Advanced)* Познакомиться с методом модели `get_absolute_url`.

## Часть 1. Конспект лекции

### 1. Проблема: Миллион страниц

Представьте, что у вас в магазине 10 000 товаров.

* **Неправильно:** Создавать 10 000 функций `view` и 10 000 путей в `urls.py` (`/product/1`, `/product/2`...).
* **Правильно:** Создать **один** шаблон и **одну** функцию, которая умеет подстраиваться под запрос.

### 2. Динамический URL (Path Converters)

В `urls.py` мы можем использовать специальные "ловушки" для параметров.
Синтаксис: `<тип_данных:имя_переменной>`.

Пример: `path('product/<int:pk>/', views.product_detail, name='product_detail')`

* `int`: Ожидаем только число. Если пользователь напишет `/product/hello/` — будет 404.
* `pk`: Имя переменной, которая уйдет в функцию-view. Обычно используют `pk` (Primary Key) или `id`.

### 3. Обработка во View

Функция теперь принимает не только `request`, но и наш параметр.

```python
# views.py
def product_detail(request, pk):
    # pk — это число из URL (например, 5)
    # Идем в базу и ищем товар с id=5
    ...
```

### 4. Обработка ошибок (404)

Что если пользователь ввел `/product/999999/`, а такого товара нет?

* `Product.objects.get(pk=999)` выбросит исключение `DoesNotExist`. Это приведет к ошибке сервера (500). Это плохо.
* **Решение:** `get_object_or_404`. Это специальная функция Django. Она пытается найти объект. Если не находит — культурно отдает ошибку 404 ("Страница не найдена").

### 5. Ссылка `{% url %}` с аргументами

Раньше мы писали `{% url 'home' %}`.
Теперь нашей ссылке нужен аргумент (ID товара).
Синтаксис: `{% url 'имя_маршрута' аргумент %}`.
Пример: `{% url 'product_detail' item.pk %}`.

## Часть 2. Практика (Live Coding)

*Преподаватель показывает процесс создания детальной страницы.*

**Шаг 1. URL**
В `urls.py`:

```python
from django.urls import path
from . import views

urlpatterns = [
    path('', views.index, name='home'),
    # Добавляем динамический маршрут
    path('item/<int:pk>/', views.item_detail, name='item_detail'),
]
```

**Шаг 2. View**
В `views.py`:

```python
from django.shortcuts import render, get_object_or_404 # Важный импорт!
from .models import Item

def item_detail(request, pk):
    item = get_object_or_404(Item, pk=pk) 
    # Если объект найден, код идет дальше. Если нет — тут всё остановится и вернется 404.
    
    context = {'item': item}
    return render(request, 'item_detail.html', context)
```

**Шаг 3. Template (Детальная страница)**
Создаем `item_detail.html`:

```html
{% extends 'base.html' %}

{% block content %}
    <h1>{{ item.title }}</h1>
    <p>Цена: {{ item.price }} руб.</p>
    <hr>
    <div>
        {{ item.description|linebreaks }}
    </div>
    <a href="{% url 'home' %}" class="btn btn-secondary">Назад к списку</a>
{% endblock %}
```

**Шаг 4. Ссылка с главной (Список)**
В `index.html` меняем кнопку "Подробнее":

```html
<!-- Было: <a href="#"> -->
<!-- Стало: -->
<a href="{% url 'item_detail' item.pk %}" class="btn btn-primary">
    Подробнее
</a>
```

## Часть 3. Домашнее задание №7

**Тема:** Реализация просмотра карточки товара/статьи.  
**Срок выполнения:** 1 неделя.  
**Максимальный балл:** 8 баллов.  

### Описание задания

Вам необходимо реализовать полноценную навигацию: пользователь должен видеть список объектов на главной, кликать на любой из них и попадать на отдельную страницу с полной информацией об этом объекте.

### Техническое задание (ТЗ)

1. **Маршрутизация (URL):**
    * Создайте новый путь в `urls.py`, который принимает `pk` (целое число).
    * Дайте маршруту понятное имя (`name=...`), например `post_detail` или `product_detail`.

2. **View-функция:**
    * Напишите функцию, которая принимает `pk`.
    * Используйте `get_object_or_404` для получения объекта из БД по этому `pk`.
    * Если объекта нет, пользователь должен видеть стандартную страницу 404 Django (не 500!).

3. **Шаблон детального просмотра:**
    * Создайте новый HTML-файл (например, `detail.html`).
    * Унаследуйте его от `base.html`.
    * Выведите **все** поля объекта (Заголовок, Полное описание, Цена, Дата, Автор и т.д.).
    * Добавьте кнопку "Назад", которая ведет на главную страницу.

4. **Связывание (Link):**
    * Вернитесь в шаблон списка (Главная страница).
    * Оберните заголовок карточки или кнопку "Читать далее" в тег `<a>`.
    * В атрибуте `href` используйте тег `{% url ... %}`, передав туда `id` (или `pk`) текущего объекта в цикле.

5. **Pro-уровень (Get Absolute URL) - *опционально, но приветствуется*:**
    * В `models.py` добавьте метод `get_absolute_url` к вашей модели.
    * Используйте функцию `reverse`.
    * В шаблоне используйте `{{ item.get_absolute_url }}` вместо длинной конструкции `{% url ... %}`.

6. **Результат работы влейте в main с коммитом "Task 7 ready."**

### Критерии оценивания (Аддитивная система)

Максимум: **8 баллов**.

| Критерий | Баллы | Описание |
| :--- | :---: | :--- |
| **URL Configuration** | **+1** | Маршрут настроен верно, используется `<int:pk>`. Именованный URL задан. |
| **Безопасность (404)** | **+2** | Использован `get_object_or_404`. При вводе несуществующего ID (например, /item/100500/) отдается ошибка 404, а не падает сервер. |
| **Детальный шаблон** | **+2** | Создан отдельный шаблон, он наследуется от `base.html`. Выводится полная информация. |
| **Навигация** | **+2** | Ссылка с главной страницы работает. Клик по товару №5 открывает страницу товара №5. |
| **Кнопка "Назад"** | **+1** | На детальной странице есть рабочая кнопка возврата к списку. |

### Штрафы

* **-2 балла:** Хардкод ссылок (например, `<a href="/item/{{ item.id }}">`).
* **-1 балл:** Использование стандартного `try...except Item.DoesNotExist` вместо шортката (это не ошибка, но мы учим best practices).
* **-1 балл:** Отсутствие наследования шаблона в детальной вьюхе (копипаста шапки и футера).
