## 1. Конспект занятия (План для преподавателя)

### Часть 1. Архитектура доступа (20 мин)

*Цель: Спроектировать матрицу доступа для нашего Файлообменника.*

**Тезисы:**

1. **Сущности:**
    * `User`: id, username, role (user/admin).
    * `FileMetadata`: id, filename, owner_id, size, created_at.
2. **Матрица прав (RBAC):**
    * **Guest:** Не видит ничего.
    * **User:**
        * Видит список *своих* файлов.
        * Может скачать/удалить *свой* файл.
        * При попытке доступа к чужому ID -> `404 Not Found` (скрываем сам факт наличия файла).
    * **Admin:**
        * Видит *все* файлы.
        * Может удалить любой файл (модерация).

### Часть 2. Подготовка базы данных (Mock) (40 мин)

*Цель: Создать структуру данных, которую будем защищать.*

**Практика (FastAPI):**

* Берем код из Урока 7 (Auth).
* Добавляем "Базу данных":

    ```python
    # Имитация БД пользователей (добавляем роль)
    users_db = {
        "alice": {"username": "alice", "role": "user", "password": "123"},
        "bob": {"username": "bob", "role": "user", "password": "456"},
        "admin": {"username": "admin", "role": "admin", "password": "000"},
    }

    # Имитация БД файлов (метаданные)
    files_db = [
        {"id": 1, "filename": "report_alice.pdf", "owner": "alice", "size": 1024},
        {"id": 2, "filename": "photo_bob.jpg", "owner": "bob", "size": 2048},
        {"id": 3, "filename": "admin_keys.txt", "owner": "admin", "size": 12},
    ]
    ```

### Часть 3. Реализация IDOR (Уязвимый код) (40 мин)

*Цель: Показать, как выглядит ошибка.*

**Практика:**
Создаем эндпоинт получения информации о файле.

```python
@app.get("/files/{file_id}")
def get_file_info(file_id: int, request: Request):
    user = request.session.get("user")
    if not user:
        raise HTTPException(401)
    
    # Поиск файла
    file = next((f for f in files_db if f["id"] == file_id), None)
    if not file:
        raise HTTPException(404)
        
    # УЯЗВИМОСТЬ: Мы вернули файл, не проверив, чей он!
    return file
```

*Демо:* Заходим как Alice, запрашиваем `/files/2` (файл Боба). Видим JSON. Это провал.

### Часть 4. Защита: Dependency Injection (60 мин)

*Цель: Написать переиспользуемую логику проверки прав.*

**Практика:**

1. Пишем зависимость `get_current_user` (извлекает юзера из сессии).
2. Пишем "умную" функцию доступа:

    ```python
    def get_file_secure(file_id: int, user_data: dict = Depends(get_current_user)):
        # 1. Находим файл
        file = next((f for f in files_db if f["id"] == file_id), None)
        
        # 2. Если файла нет - 404
        if not file:
            raise HTTPException(404)
            
        # 3. Логика RBAC + Ownership
        is_owner = file["owner"] == user_data["username"]
        is_admin = user_data["role"] == "admin"
        
        if not (is_owner or is_admin):
            # ВАЖНО: Возвращаем 404, чтобы хакер не мог брутфорсить ID файлов
            raise HTTPException(404, detail="File not found") 
            
        return file
    ```

3. Внедряем зависимость в эндпоинт:

    ```python
    @app.get("/files/{file_id}")
    def read_file(file: dict = Depends(get_file_secure)):
        return file
    ```

### Часть 5. Тестирование скриптом (20 мин)

*Цель: Автоматизировать проверку безопасности.*

**Тезисы:**

    2. GET /files/1 -> OK.
    3. GET /files/2 -> 404 (хотя файл 2 существует!).

## 2. Домашнее задание №8: «Чужие здесь не ходят»

**Легенда:**
Наш "Файлообменник" обрастает функционалом. Пользователи начали загружать отчеты, но тут же посыпались жалобы, что любой желающий может удалить чужой отчет, просто перебирая цифры в адресной строке.
Вам поручено реализовать строгую систему контроля доступа (RBAC), чтобы защитить данные, и добавить возможность Администратору наводить порядок.

**Задание:**

1. **Интеграция:**
    * Продолжайте работать в репозитории проекта.
    * Добавьте (или обновите) структуру данных `users` (обязательно добавьте поле `role`: 'user' или 'admin').
    * Создайте список `files_db` (минимум 3 файла: один Алисы, один Боба, один Админа).

2. **Реализация защищенного доступа (Чтение):**
    * Создайте эндпоинт `GET /files/{file_id}`.
    * Напишите Dependency (зависимость) `check_file_permissions`.
    * **Логика:**
        * Админ видит любой файл.
        * Владелец видит свой файл.
        * Посторонний получает **404 Not Found** (Security through Obscurity).
    * *Примечание:* Реальный контент файла отдавать не нужно, достаточно вернуть JSON с метаданными (имя, размер, владелец).

3. **Реализация защищенного удаления (Удаление):**
    * Создайте эндпоинт `DELETE /files/{file_id}`.
    * Используйте ту же зависимость (или напишите новую, если логика отличается).
    * При успешном удалении файл должен пропадать из `files_db`.

4. **Endpoint "Мои файлы":**
    * Реализуйте `GET /files/my`.
    * Он должен возвращать список **только** тех файлов, которые принадлежат текущему пользователю.
    * *Для Админа:* Можно сделать `GET /files/all`, который вернет всё.

5. **Автотесты безопасности:**
    * Напишите скрипт `test_security.py` (используя `requests` или `pytest`), который выполняет следующие проверки:
        * **Test 1 (IDOR):** Пользователь А пытается получить файл Пользователя Б -> Ожидается статус 404.
        * **Test 2 (Access):** Пользователь А получает свой файл -> Ожидается статус 200.
        * **Test 3 (Admin):** Админ удаляет файл Пользователя Б -> Ожидается статус 200 (и файл реально исчезает).

6. **Деплой на сервер (Linux):**
    * Закоммитьте изменения.
    * Зайдите на ваш учебный сервер (по SSH).
    * Сделайте `git pull`.
    * Обновите зависимости (`pip install -r requirements.txt`).
    * **Важно:** Обновите файл `.env` на сервере, если нужно (через `nano .env`).
    * Перезапустите приложение (Uvicorn).

**Формат сдачи:**

1. Ссылка на репозиторий.
2. Отчет в формате Markdown содержащий:
    * Файл `test_security.py`.
    * Скриншот терминала с успешным запуском тестов (все тесты passed).
3. **Результат работы влейте в main с коммитом "Task 8 ready."**

## 3. Критерии оценивания (Максимум 8 баллов)

| Критерий | Баллы | Описание |
| :--- | :---: | :--- |
| **RBAC Logic** | **1** | Реализована ролевая модель (User vs Admin). Админ имеет полные права. |
| **IDOR Protection (GET)** | **1** | Реализована защита от чтения чужих файлов. Возвращается 404 (или 403) при попытке доступа к чужому ресурсу. |
| **Secure Delete** | **1** | Удаление файла также защищено (нельзя удалить чужой файл, если ты не админ). |
| **Список файлов** | **1** | Эндпоинт `/files/my` фильтрует список и показывает только файлы пользователя. |
| **Автотесты** | **2** | Представлен работающий скрипт, покрывающий кейсы "Взлом" и "Нормальная работа". |
| **Работа на сервере (Деплой)** | **2** | Приложение успешно развернуто на сервере (git pull), функционал работает удаленно. |
| **Итого** | **8** | |

### Штрафы

* **-2 балла:** Критическая уязвимость IDOR (тест "Пользователь А читает файл Б" проходит успешно, возвращая данные).
* **-1 балл:** Возврат ошибки 500 при ненайденном файле (плохая обработка исключений).
* **-1 балл:** Логика проверки скопирована в каждый эндпоинт (Violation of DRY), вместо использования Dependency.
