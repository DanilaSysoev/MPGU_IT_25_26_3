## 1. Конспект занятия (План для преподавателя)

### Часть 1. Теория: SAST vs DAST (30 мин)

*Цель: Понять разницу подходов.*

**Тезисы:**

1. **SAST (White Box):**
    * Смотрит код.
    * Видит: `eval(user_input)`, SQL-инъекции, хардкод паролей.
    * Не видит: Проблемы конфигурации сервера, логические ошибки.
    * Плюсы: Быстро, дешево, находит место в коде.
    * Минусы: Много False Positives (ложных срабатываний).
2. **DAST (Black Box):**
    * Не видит код, работает как хакер.
    * Отправляет `../../etc/passwd` в форму, смотрит ответ.
    * Плюсы: Находит реальные дыры (XSS, SQLi), проверяет заголовки (CSP, HSTS).
    * Минусы: Медленно, может положить сервер (DoS).

### Часть 2. SAST: Bandit (Python) (50 мин)

*Цель: Найти дыры в своем коде.*

**Практика:**

1. **Установка:** `pip install bandit`.
2. **Запуск:** `bandit -r .` (рекурсивно сканировать текущую папку).
3. **Анализ отчета:**
    * `Issue: [B101:assert_used] Use of assert detected.` (В Python `assert` вырезается при оптимизации `-O`, нельзя использовать для проверки безопасности).
    * `Issue: [B303:md5] Use of insecure MD5 hash function.`
    * `Issue: [B105:hardcoded_password_string] Possible hardcoded password.`
4. **Игнорирование:** Если мы уверены, что всё ок (например, MD5 нужен для контрольной суммы файла, а не пароля), добавляем `# nosec` в конце строки.

**Интеграция:**
Добавляем Bandit в наш любимый `.pre-commit-config.yaml` или в CI пайплайн (GitHub Actions, если успеем).

### Часть 3. DAST: OWASP ZAP (Zed Attack Proxy) (60 мин)

*Цель: Просканировать запущенное приложение.*

**Инструмент:** **ZAP** (бесплатный, мощный, но с GUI). Для CI есть **ZAP CLI** или Docker-образ.
Мы будем использовать **Docker-образ** для простоты (Baseline Scan).

**Практика:**

1. Запускаем наше приложение (`docker-compose up -d`). Его сетевой адрес можно посмотреть с помощью команды `echo $(ip -f inet -o addr show docker0 | awk '{print $4}' | cut -d '/' -f 1)`.
2. Запускаем ZAP в докере:

    ```bash
    docker run -t zapproxy/zap-stable zap-baseline.py \
        -t http://$(ip -f inet -o addr show docker0 | awk '{print $4}' | cut -d '/' -f 1)/docs
    ```

3. **Анализ:**
    * "X-Content-Type-Options Header Missing".
    * "Cookie No HttpOnly Flag".
    * "Cross-Domain Misconfiguration".

### Часть 4. Интеграция в CI (GitHub Actions) (40 мин)

*Цель: Автоматизировать проверку при каждом пуше.*

**Практика:**

1. Создаем `.github/workflows/security.yml`.
2. Добавляем Job `sast`:

    ```yaml
    name: Security Check
    on: [push]
    jobs:
      bandit:
        runs-on: ubuntu-latest
        steps:
          - uses: actions/checkout@v2
          - name: Run Bandit
            uses: PyCQA/bandit-action@v1.2.0
            with:
              args: "-r . -ll"  # -ll: только Medium/High severity
    ```

3. Пушим код. Смотрим вкладку "Actions" на GitHub. Видим зеленый или красный статус.

## 2. Домашнее задание №14: «Аудит перед релизом»

**Легенда:**
Проект почти готов к сдаче. Заказчик требует отчет о безопасности. Вы должны прогнать код через статический анализатор, исправить все найденные критические ошибки и настроить автоматическую проверку, чтобы "джуниоры" не сломали безопасность в будущем.

**Задание:**

1. **SAST (Bandit):**
    * Установите `bandit`.
    * Запустите сканирование вашего проекта (`secure_file_manager`): `bandit -r . -f json -o bandit_report.json`.
    * **Исправьте** все найденные ошибки уровня **High** и **Medium**. (Например, уберите `assert`, замените слабые хэши, уберите хардкод).
    * Если ошибка — ложное срабатывание (например, `subprocess` используется безопасно), пометьте строку комментарием `# nosec`.

2. **Pre-commit Hook:**
    * Добавьте Bandit в `.pre-commit-config.yaml`.
    * Убедитесь, что он запускается при коммите.

3. **GitHub Actions (CI/CD):**
    * Создайте workflow `.github/workflows/security.yml`.
    * Настройте запуск Bandit при каждом `push`.
    * Сделайте пуш (с исправленным кодом).
    * Убедитесь, что Action прошел успешно (зеленая галочка).

4. **DAST (ZAP) - Опционально/Бонус:**
    * Запустите ZAP Baseline Scan (через Docker) на ваш запущенный локально сервис.
    * Сохраните вывод консоли в файл `zap_report.txt`.
    * Посмотрите, ругается ли он на заголовки (CSP, X-Frame-Options). Если да — добавьте их в Middleware (как в Уроке 6).

**Формат сдачи:**

1. Ссылка на репозиторий (с файлом workflow).
2. Отчет (`report_14.md`):
    * Скриншот локального запуска Bandit (до и после исправлений).
    * Скриншот вкладки GitHub Actions с успешным прохождением теста.
    * (Бонус) Отчет ZAP.
3. **Результат работы влейте в main с коммитом "Task 14 ready."**
