## 1. Конспект занятия (План для преподавателя)

### Часть 1. Теория: Правило №1 криптографии (30 мин)

*Цель: Объяснить, почему нельзя писать свои алгоритмы шифрования.*

**Тезисы:**

1. **Don't Roll Your Own Crypto:** Никогда не пишите функции `xor_encrypt` или сдвиг битов. Их взломают за 5 минут. Используйте только проверенные библиотеки.
2. **Symmetric vs Asymmetric:**
    * *Симметричное (AES, ChaCha20):* Один ключ для закрытия и открытия. Быстрое. Подходит для шифрования файлов и дисков. (Наш выбор сегодня).
    * *Асимметричное (RSA, ECC):* Публичный и Приватный ключи. Медленное. Нужно для обмена ключами (HTTPS, SSH).
3. **Data at Rest vs Data in Transit:**
    * HTTPS защищает канал (трубу).
    * AES защищает диск (склад). Если хакер вынес сервер из дата-центра, HTTPS не поможет. Шифрование диска — поможет.

### Часть 2. Инструментарий: Библиотека `cryptography` (40 мин)

*Цель: Освоить стандарт де-факто в Python.*

**Практика:**

1. **Установка:** `pip install cryptography`.
2. **Fernet (Symmetric Encryption):** Это реализация AES-128 в режиме CBC с подписью HMAC (защита от изменения данных) и ротацией IV (каждое шифрование одного и того же текста дает разный результат). "Батарейки в комплекте".
3. **Генерация ключа:**

    ```python
    from cryptography.fernet import Fernet
    
    # Генерируем ключ (один раз!)
    key = Fernet.generate_key()
    print(key) # b'...'
    
    # Инициализация
    cipher_suite = Fernet(key)
    
    # Шифрование
    text = b"Secret Message"
    encrypted_text = cipher_suite.encrypt(text) # Выглядит как мусор
    
    # Расшифровка
    decrypted_text = cipher_suite.decrypt(encrypted_text)
    ```

### Часть 3. Управление ключами (Key Management) (30 мин)

*Цель: Понять, что потеря ключа = потеря данных.*

**Тезисы:**

1. **Где хранить ключ?**
    * В коде? НЕТ. (Урок 3).
    * В БД рядом с данными? НЕТ. (Если украдут дамп БД, украдут и ключ).
    * **В переменных окружения (`.env`):** ДА.
2. **Потеря ключа:** Если вы удалили `.env` и не сделали бэкап ключа — файлы превращаются в цифровой мусор навсегда.
3. **Ротация:** Периодическая смена ключей (decrypt old -> encrypt new). Обсудим теоретически.

**Практика:**

* Добавляем `ENCRYPTION_KEY=...` в наш `.env`.
* Читаем его через `os.getenv` при старте приложения.

### Часть 4. Реализация "Секретной загрузки" (60 мин)

*Цель: Интегрировать шифрование в File Manager.*

**Архитектура:**

1. Добавляем флаг `is_secret` (bool) в модель файла БД.
2. При загрузке: Если пользователь поставил галочку "Encrypt":
    * Читаем файл.
    * Шифруем байты через `Fernet`.
    * Сохраняем зашифрованные байты на диск.
3. При скачивании:
    * Читаем файл с диска.
    * Смотрим в БД: если `is_secret == True` -> Расшифровываем.
    * Отдаем пользователю чистые данные.

**Live Coding:**
Модифицируем эндпоинты `upload` и `download` из Урока 9.
*Обратите внимание: Fernet загружает весь файл в память. Для файлов >100МБ нужно потоковое шифрование, но для учебных целей ограничим размер файла.*

### Часть 5. Демонстрация взлома (20 мин)

*Цель: Убедиться, что это работает.*

**Сценарий:**

1. Загружаем файл "salary.pdf" с шифрованием.
2. Идем в папку `storage` на сервере.
3. Пытаемся открыть файл PDF-ридером или блокнотом.
4. Видим ошибку или "кашу".
5. Скачиваем через API — файл открывается. Магия!

## 2. Домашнее задание №10: «Совершенно секретно»

**Легенда:**
Финансовый отдел требует функцию безопасного хранения отчетов. Даже если системный администратор зайдет на сервер и скопирует папку с файлами, он не должен прочитать содержимое зарплатных ведомостей.
Ваша задача — реализовать опциональное шифрование файлов "на лету".

**Задание:**

1. **Подготовка:**
    * Сгенерируйте ключ шифрования (`Fernet.generate_key()`).
    * Добавьте его в локальный `.env` и в `.env.example` (как заглушку).
    * Обновите модель БД (`files_db`): добавьте поле `is_encrypted: bool`.

2. **Модификация Upload (`POST /files/upload`):**
    * Добавьте query-параметр `encrypt: bool = False`.
    * Если `encrypt=True`:
        * Зашифруйте содержимое файла перед сохранением на диск.
        * Сохраните в БД флаг `is_encrypted=True`.
    * *Подсказка:* `file_data = await file.read(); encrypted_data = cipher.encrypt(file_data)`.

3. **Модификация Download (`GET /files/{id}`):**
    * Перед отдачей файла проверьте флаг `is_encrypted`.
    * Если `True`: Считайте файл с диска -> Расшифруйте -> Отдайте результат пользователю.
    * Если `False`: Отдайте файл как есть (для старых файлов).

4. **Деплой на сервер (Linux):**
    * Закоммитьте изменения (код + `requirements.txt`).
    * Зайдите на ваш учебный сервер (по SSH).
    * Сделайте `git pull`.
    * Обновите зависимости (`pip install -r requirements.txt`).
    * **Важно:** Добавьте сгенерированный ключ шифрования в файл `.env` на сервере (через `nano .env`). Ключ должен совпадать с тем, что вы использовали, или быть новым (но старые файлы не откроются).
    * Перезапустите приложение (Uvicorn).

5. **Демонстрация (Proof of Concept):**
    * Загрузите секретный текстовый файл (`secret.txt`) с флагом `encrypt=True` на *сервер*.
    * Скачайте этот файл через API (он должен читаться).
    * Зайдите на сервер по SSH и попробуйте прочитать этот файл командой `cat storage/<uuid>`. Вы должны увидеть зашифрованный мусор (base64 строку), а не исходный текст.

**Формат сдачи:**

1. Ссылка на репозиторий.
2. Отчет (`report_10.md`):
    * Скриншот локального файла `.env` (замажьте часть ключа).
    * Скриншот терминала **сервера**, где вы делаете `cat storage/...` и видите зашифрованный текст.
    * Скриншот браузера/Postman, где вы скачали этот же файл через API и видите читаемый текст.
3. **Результат работы влейте в main с коммитом "Task 10 ready."**
