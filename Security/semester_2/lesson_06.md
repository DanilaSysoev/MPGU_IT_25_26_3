## 1. Конспект занятия (План для преподавателя)

### Часть 1. Теория: Как скрипт попадает в браузер? (30 мин)

*Цель: Понять механику атаки.*

**Тезисы:**

1. **Суть XSS:** Сервер берет данные от пользователя и "вклеивает" их в HTML-страницу без проверки. Браузер думает, что это код страницы, и выполняет его.
2. **Типы XSS:**
    * **Reflected (Отраженная):** Ссылка вида `site.com/search?q=<script>alert(1)</script>`. Сервер эхом возвращает запрос на страницу. Жертва должна кликнуть по ссылке.
    * **Stored (Хранимая):** Злоумышленник пишет комментарий с вирусом. Комментарий сохраняется в БД. Каждый, кто заходит на страницу, заражается. (Наш случай в курсовом проекте).
3. **Последствия:**
    * Кража `document.cookie` (сессии).
    * Редирект на фишинговый сайт.
    * Действия от имени пользователя (лайки, переводы денег).

### Часть 2. Создаем уязвимость (Jinja2 & FastAPI) (50 мин)

*Цель: Сделать "дырявую" страницу.*

**Практика:**

1. **Установка:** `pip install jinja2`.
2. **Настройка шаблонов:** Создаем папку `templates` и файл `index.html`.
3. **Код (FastAPI):**

    ```python
    from fastapi import FastAPI, Request
    from fastapi.templating import Jinja2Templates

    app = FastAPI()
    templates = Jinja2Templates(directory="templates")

    @app.get("/")
    def read_root(request: Request, name: str = "Guest"):
        # ОПАСНО: передаем данные в шаблон
        return templates.TemplateResponse("index.html", {"request": request, "name": name})
    ```

4. **Шаблон (index.html):**
    * В Jinja2 по умолчанию включено автоэкранирование. Чтобы показать уязвимость, мы его **отключим** (симуляция старого кода или ошибки разработчика): `{{ name | safe }}`.
5. **Атака:** Переходим по ссылке `http://localhost:8000/?name=<script>alert('XSS')</script>`. Видим всплывающее окно. **Победа (или поражение).**

### Часть 3. Лечение: Экранирование и Санитизация (50 мин)

*Цель: Научиться очищать HTML.*

**Тезисы:**

1. **Escaping (Экранирование):** Превращение спецсимволов в безопасные сущности (`<` -> `&lt;`, `>` -> `&gt;`). Браузер рисует скобку, но не исполняет тег.
    * *В Jinja2:* Просто уберите `| safe`. Это защита по умолчанию.
2. **Sanitization (Санитизация):** Что если мы *хотим* разрешить пользователю писать **жирным** (`<b>`), но запретить скрипты?
    * Экранирование убьет всё. Нужен "умный фильтр".
    * Библиотека **Bleach** (стандарт индустрии в Python).

**Практика:**

* `pip install bleach`.
* Пишем функцию `clean_text(text: str)`:

    ```python
    import bleach
    def clean_text(text):
        return bleach.clean(text, tags=['b', 'i'], attributes={}, strip=True)
    ```

* Пробуем передать `<script>alert(1)</script><b>Hello</b>`. Скрипт исчезает, жирный текст остается.

### Часть 4. Content Security Policy (CSP) (50 мин)

*Цель: "Бронежилет" для сайта.*

**Тезисы:**

1. **Что это?** HTTP-заголовок, в котором сервер говорит браузеру: "Загружай скрипты и картинки ТОЛЬКО с этих доменов".
2. **Пример:** `Content-Security-Policy: default-src 'self'`. Запрещает всё стороннее и *инлайн-скрипты* (те, что прямо в HTML).
3. **В FastAPI:** Добавляем заголовок в Middleware или прямо в ответе (`response.headers`).

    * **Вариант 1. Глобальная защита (Рекомендуемый)**  
    Мы создаем middleware (промежуточный слой), который добавляет заголовок CSP ко **всем** ответам сервера автоматически.

        ```python
        from fastapi import FastAPI, Request

        app = FastAPI()

        # Middleware для добавления заголовков безопасности
        @app.middleware("http")
        async def add_security_headers(request: Request, call_next):
            response = await call_next(request)
            
            # Настройка CSP:
            # default-src 'self' - по умолчанию загружаем всё только с нашего домена
            # script-src 'self' - скрипты только свои (никаких inline-скриптов и чужих CDN!)
            # style-src 'self' - стили только свои (можно добавить 'unsafe-inline' для style, если очень нужно)
            # img-src 'self' data: - картинки свои + разрешаем base64 (data:)
            policy = (
                "default-src 'self'; "
                "script-src 'self'; "  # Самое важное: блокирует <script>alert(1)</script>
                "style-src 'self'; "
                "img-src 'self' data:;"
            )
            
            response.headers["Content-Security-Policy"] = policy
            return response

        @app.get("/")
        def read_root():
            return {"message": "I am protected by CSP!"}
        ```

    * **Вариант 2. Локальная защита (В конкретном эндпоинте)**  
    Если нужно защитить только одну страницу (например, страницу с комментариями), можно передать заголовки прямо в `TemplateResponse`.

        ```python
        from fastapi import FastAPI, Request
        from fastapi.templating import Jinja2Templates

        app = FastAPI()
        templates = Jinja2Templates(directory="templates")

        @app.get("/comments")
        def get_comments(request: Request):
            # Строгая политика только для этой страницы
            csp_policy = "default-src 'self'; script-src 'self'; object-src 'none';"
            
            return templates.TemplateResponse(
                "comments.html", 
                {"request": request, "comments": []},
                # Передаем заголовок здесь
                headers={"Content-Security-Policy": csp_policy}
            )
        ```

    * **Вариант 3. Если студенты используют CDN (например, Bootstrap)**  
    Если студент подключил Bootstrap через ссылку (CDN), строгий CSP `default-src 'self'` сломает дизайн. Нужно разрешить конкретный домен.

        ```python
        # Пример политики, разрешающей Bootstrap CDN
        policy = (
            "default-src 'self'; "
            "style-src 'self' https://cdn.jsdelivr.net; " # Разрешаем стили с CDN
            "script-src 'self' https://cdn.jsdelivr.net; " # Разрешаем скрипты с CDN
        )
        response.headers["Content-Security-Policy"] = policy
        ```

**Практика:**

* Добавляем заголовок CSP в наш эндпоинт.
* Снова пытаемся выполнить XSS-атаку.
* Открываем консоль разработчика (F12) и видим красную ошибку: *"Refused to execute inline script because it violates the following Content Security Policy..."*. Браузер заблокировал атаку, даже если мы забыли про санитизацию!

## 2. Домашнее задание №6: «Стена плача (и комментариев)»

**Легенда:**
В нашем "Файловом менеджере" появилась новая фича — возможность оставлять публичные объявления (или комментарии к файлам). Руководство хочет, чтобы сотрудники могли выделять текст **жирным** и *курсивом*, но категорически запрещает любые скрипты. Ваша задача — реализовать этот функционал безопасно.

**Задание:**

1. **Подготовка:**
    * В проект добавьте папку `templates/` и файл `comments.html` (простая форма: поле ввода текста + кнопка "Отправить" + список прошлых комментариев).
    * Установите `jinja2` и `bleach`.

2. **Реализация уязвимости (для теста):**
    * Создайте эндпоинт `GET /comments` (показывает страницу) и `POST /comments` (принимает текст).
    * Временно выведите комментарий в шаблоне с фильтром `| safe` (или отключив экранирование).
    * **Сделайте скриншот**, где вы вводите `<img src=x onerror=alert('Hacked')>` и получаете всплывающее окно `alert`. Это доказательство, что система уязвима.

3. **Защита №1: Санитизация (Bleach):**
    * Напишите функцию очистки текста. Разрешите только теги `['b', 'i', 'u', 'em', 'strong']`. Все остальные теги (особенно `script`, `img`, `iframe`) должны удаляться или экранироваться.
    * Примените эту функцию к данным *перед* передачей их в шаблон.
    * Уберите `| safe` (или используйте результат работы bleach).
    * **Проверка:** Попробуйте отправить `<b>Важное</b> <script>alert(1)</script>`. На странице должно остаться только "Важное" (жирным), скрипта быть не должно.

4. **Защита №2: CSP (Content Security Policy):**
    * Добавьте в ответ сервера заголовок `Content-Security-Policy`.
    * Политика должна быть строгой: `default-src 'self'; script-src 'self'; style-src 'self'`. (Можно разрешить CDN, если используете Bootstrap, но лучше всё локально).
    * **Сделайте скриншот** DevTools (вкладка Console), где видно, что браузер заблокировал попытку исполнения инлайн-скрипта (даже если бы он прошел через фильтры).

5. **Деплой на сервер (Linux):**
    * Закоммитьте изменения.
    * Зайдите на ваш учебный сервер (по SSH).
    * Сделайте `git pull`.
    * Обновите зависимости (`pip install -r requirements.txt`).
    * **Важно:** Обновите файл `.env` на сервере, если нужно (через `nano .env`).
    * Перезапустите приложение (Uvicorn).

**Формат сдачи:**

1. Код проекта (ссылка на Git).
2. Отчет (`security_report_06.md`):
    * Скриншот успешной XSS-атаки (до защиты).
    * Пример кода функции-санитизера.
    * Скриншот заголовков ответа (вкладка Network), где виден CSP.
    * Скриншот заблокированной атаки (из консоли браузера).
