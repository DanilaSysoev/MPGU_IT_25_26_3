# Урок 15. Воркшоп по доработке и интеграции (Sprint Final)

**Тип занятия:** Практический спринт (Sprint / Hackathon)  
**Продолжительность:** 3 астрономических часа (180 мин)  
**Формат:** Работа в командах (если были команды) или индивидуально + Code Review с преподавателем.  
**Цель:** Подготовить MVP (Minimum Viable Product) к защите  

---

## 1. Конспект занятия (План для преподавателя)

### Часть 1. Чек-лист готовности (30 мин)

*Цель: Провести самодиагностику проектов.*

**Преподаватель выводит на экран (или раздает) чек-лист "Ready for Prod":**

1. **Инфраструктура:**
    * [ ] `docker-compose up --build` поднимает всё (App, DB) без ошибок.
    * [ ] Данные (файлы и БД) сохраняются при перезапуске (Volume).
    * [ ] `.env` файл не закоммичен, но есть `.env.example`.
2. **Безопасность (AppSec):**
    * [ ] Пароли хэшируются (bcrypt/argon2)? (Мы использовали заглушки в уроках, сейчас время подключить `passlib`).
    * [ ] Эндпоинты защищены JWT/Session? (Нельзя зайти без логина).
    * [ ] Чужие файлы недоступны (IDOR)? (Вернуть 404/403).
    * [ ] Загрузка файлов проверяет тип (magic bytes) и переименовывает (UUID)?
3. **Code Quality:**
    * [ ] Нет `print()`, только `logger`.
    * [ ] Нет хардкода секретов.
    * [ ] Linter (flake8/black) и SAST (bandit) проходят без ошибок.
4. **Документация:**
    * [ ] `README.md`: Как запустить проект одной командой?

### Часть 2. Спринт: "Лечение долгов" (120 мин)

*Цель: Закрыть дыры.*

**Роль преподавателя:**

* Ходить между студентами (или по комнатам в Zoom).
* Смотреть код.
* Помогать с "непонятными ошибками Докера".
* **Челлендж:** Попробовать "взломать" соседа. (Если студенты готовы, можно устроить мини-CTF: дай IP соседу, пусть попробует скачать чужой файл).

**Типичные проблемы, которые нужно решить:**

1. *"У меня на винде пути `\` а в докере `/`"* -> Используем `pathlib`.
2. *"База данных не успевает подняться до приложения"* -> Добавляем `healthcheck` в docker-compose или скрипт `wait-for-it.sh`.
3. *"Я забыл про шифрование"* -> Быстро прикручиваем Fernet из Урока 10.

### Часть 3. Подготовка к демо (30 мин)

*Цель: Научить продавать свою работу.*

**Сценарий защиты (Урок 16):**

1. **Запуск:** Студент клонирует репо на чистую машину (или демонстрирует экран), делает `docker-compose up`.
2. **Демо функционала:**
    * Регистрация юзера.
    * Загрузка "секретного документа" (PDF).
    * Попытка скачать его под другим юзером (Фейл).
    * Скачивание под своим юзером (Успех).
3. **Ответы на вопросы:** "А что если я загружу `shell.php`?", "А где лежат ключи шифрования?".

## 2. Домашнее задание №15: «Финишная прямая»

**Легенда:**
Через неделю — релиз. У вас есть последний шанс привести код в порядок, написать инструкцию для админов (`README.md`) и убедиться, что приложение не стыдно показать заказчику.

**Задание:**

1. **Code Review (Self):**
    * Прогоните весь проект через чеклист из Части 1.
    * Исправьте все `TODO`, которые вы оставляли "на потом".

2. **README.md (Обязательно):**
    * Напишите качественную документацию в корне репозитория.
    * **Содержание:**
        * Название и описание проекта.
        * Технологии (FastAPI, Docker, Postgres, Fernet).
        * **Инструкция по запуску:**
            1. `git clone ...`
            2. `cp .env.example .env`
            3. `docker-compose up -d`
        * Описание API (можно ссылку на `/docs` или скриншот Swagger).

3. **Финальные штрихи:**
    * Убедитесь, что миграции БД (если есть) накатываются автоматически.
    * Проверьте, что логи пишутся в volume.

4. **Видео-демо (Опционально, но круто):**
    * Запишите 2-минутное видео (скринкаст), где вы показываете работу основных функций. Это страховка на случай "демо-эффекта" на защите.

**Формат сдачи:**

1. Ссылка на финальный репозиторий (ветка `main` или `master`). В репозитории должен быть идеальный `README.md`.
2. **Результат работы влейте в main с коммитом "Task 15 ready."**
