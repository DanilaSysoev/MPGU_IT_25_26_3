## 1. Конспект занятия (План для преподавателя)

### Часть 1. Теория: Файл — это не то, чем он кажется (30 мин)

*Цель: Объяснить векторы атак через загрузку.*

**Тезисы:**

1. **Path Traversal (Zip Slip / Directory Traversal):**
    * Хакер отправляет файл с именем `../../../../etc/passwd`.
    * Если код делает `open("uploads/" + filename, "w")`, он перезапишет системный файл (если хватит прав) или положит файл вне папки `uploads`.
2. **Двойные расширения и Null-byte:**
    * `shell.php.jpg` (сервер проверяет конец, а Apache исполняет первое расширение).
    * `shell.php%00.jpg` (в старых системах строка обрывалась на `%00`).
3. **MIME-Types spoofing:**
    * Браузер шлет заголовок `Content-Type: image/jpeg`, но внутри файла — PHP-скрипт. Верить заголовкам нельзя!
4. **XSS через файлы:** Загрузка SVG или HTML файла с JS внутри. Если сервер отдаст его как `text/html`, скрипт выполнится.

### Часть 2. Path Traversal (Взлом и Защита) (50 мин)

*Цель: Научиться "выходить из комнаты" и запирать дверь.*

**Практика (Уязвимый код):**

* Создаем эндпоинт загрузки:

    ```python
    @app.post("/upload_vulnerable")
    async def upload(file: UploadFile):
        # УЯЗВИМОСТЬ: Доверяем имени файла от пользователя
        with open(f"uploads/{file.filename}", "wb") as buffer:
            shutil.copyfileobj(file.file, buffer)
        return {"filename": file.filename}
    ```

* **Атака (через curl или Postman):**
  * Пытаемся передать файл с именем `../hacked.txt`.
  * Смотрим, появился ли файл на уровень выше папки `uploads`.
* **Защита (Радикальная):**
  * **Никогда** не использовать имя файла от пользователя для сохранения на диск.
  * Генерируем **UUID**: `uuid.uuid4()`.
  * Сохраняем: `physical_name = f"{uuid4()}.bin"`.
  * Оригинальное имя храним только в БД для отображения.

### Часть 3. Проверка содержимого (Magic Numbers) (50 мин)

*Цель: Отличить кота от вируса.*

**Тезисы:**

1. Расширение `.jpg` можно приписать к чему угодно.
2. **Магические числа (Сигнатуры):** Первые байты файла.
    * JPEG: `FF D8 FF`
    * PNG: `89 50 4E 47`
    * PDF: `%PDF`
3. Инструмент: `python-magic` (Linux/Mac) или `filetype` (кроссплатформенно, проще для Windows). Мы возьмем **`filetype`** или встроенную проверку первых байт, чтобы не мучиться с зависимостями `libmagic` на Windows.

**Практика:**

* `pip install filetype`.
* Читаем заголовок (head) файла (первые 2 КБ).
* Проверяем тип:

    ```python
    import filetype
    
    # Читаем первые 2048 байт (не весь файл!)
    head = await file.read(2048)
    kind = filetype.guess(head)
    
    if kind is None or kind.mime not in ["image/jpeg", "image/png", "application/pdf"]:
        raise HTTPException(400, "Only images and PDF allowed")
        
    # Важно: Сбросить каретку в начало перед сохранением!
    await file.seek(0)
    ```

### Часть 4. DoS и Ограничение размера (30 мин)

*Цель: Не дать положить сервер гигабайтным файлом.*

**Тезисы:**

1. Если начать читать файл в память (`file.read()`), сервер с 2ГБ RAM упадет от файла в 3ГБ.
2. **Stream Processing:** Читаем и пишем кусками (chunks).
3. **Проверка размера:**
    * Либо на уровне Nginx (в продакшене).
    * Либо считаем байты при чтении чанков.

**Практика:**

* Пишем цикл сохранения чанками по 1МБ.
* Если сумма байт > `MAX_SIZE` (например 5МБ), прерываем загрузку и удаляем частично записанный файл.

### Часть 5. Интеграция с БД (20 мин)

*Цель: Связать файл на диске с записью в БД.*

**Архитектура:**

* **Папка хранения:** `storage/` (вне веб-рута, если возможно, или закрытая конфигом).
* **БД:**
  * `id`: 1
  * `original_name`: "cat.jpg"
  * `physical_path`: "storage/a1b2-c3d4..." (UUID)
  * `owner_id`: 42

## 2. Домашнее задание №9: «Надежное хранилище»

**Легенда:**
Наш "Файлообменник" наконец-то начинает работать с файлами! Ваша задача — реализовать безопасную загрузку и скачивание. Вы должны гарантировать, что пользователь не сможет перезаписать системные файлы, загрузить `.exe` под видом картинки или положить сервер огромным файлом.

**Задание:**

1. **Подготовка:**
    * Создайте папку `storage` в корне проекта (добавьте её в `.gitignore`!).
    * Установите `filetype` (или аналогичную библиотеку).

2. **Эндпоинт загрузки (`POST /files/upload`):**
    * Принимает файл (`UploadFile`).
    * **Проверка 1 (Размер):** Если файл больше **2 МБ**, сервер должен прервать соединение и вернуть ошибку 413 (Entity Too Large). *Подсказка: проверяйте размер, вычитывая файл, или через `spool_max_size` (но лучше вручную).*
    * **Проверка 2 (Тип):** Разрешены только: `image/jpeg`, `image/png`. Проверка должна быть по **содержимому** (Magic bytes), а не по расширению.
    * **Сохранение:**
        * Сгенерируйте UUID имя.
        * Сохраните файл в папку `storage` с новым именем.
    * **БД:** Сохраните метаданные в `files_db` (из Урока 8):
        * `owner`: текущий юзер.
        * `original_name`: то, что прислал юзер.
        * `path`: путь к UUID файлу.
        * `size`: размер.

3. **Эндпоинт скачивания (`GET /files/{file_id}/download`):**
    * Используйте проверку прав из Урока 8 (чужой файл скачать нельзя).
    * Найдите файл на диске по `path`.
    * Верните `FileResponse` (из `fastapi.responses`).
    * **Важно:** Установите имя скачиваемого файла равным `original_name` (чтобы пользователь скачал "cat.jpg", а не "a1b2...").
    * Установите заголовок `Content-Disposition`, чтобы файл скачивался, а не открывался в браузере (защита от XSS в SVG/HTML).

4. **Сценарий атаки (Тест):**
    * Возьмите любой текстовый файл, переименуйте его в `fake.jpg`.
    * Попробуйте загрузить. Сервер должен вернуть ошибку (так как сигнатура не JPEG).
    * **Сделайте скриншот** ошибки.

5. **Деплой на сервер (Linux):**
    * Закоммитьте изменения.
    * Зайдите на ваш учебный сервер (по SSH).
    * Сделайте `git pull`.
    * Обновите зависимости (`pip install -r requirements.txt`).
    * **Важно:** Обновите файл `.env` на сервере, если нужно (через `nano .env`).
    * Перезапустите приложение (Uvicorn).

**Формат сдачи:**

1. Репозиторий проекта (обновленные `main.py`, папка `storage` не нужна).
2. Отчет:
    * Скриншот папки `storage`, где лежат файлы с UUID-именами.
    * Скриншот ответа сервера при попытке загрузить `fake.jpg` (текстовый файл с неправильным расширением).
    * Скриншот успешного скачивания файла (в браузере видно оригинальное имя).
3. **Результат работы влейте в main с коммитом "Task 9 ready."**

## 3. Критерии оценивания (Максимум 8 баллов)

| Критерий | Баллы | Описание |
| :--- | :---: | :--- |
| **UUID Naming** | **1** | Файлы на диске сохранены под UUID именами. Оригинальное имя игнорируется при сохранении (защита от Path Traversal). |
| **Magic Bytes Check** | **2** | Реализована проверка типа файла по содержимому (`filetype` или аналоги). Переименованные `.exe` или `.txt` не проходят. |
| **Content-Disposition** | **1** | При скачивании файл отдается с оригинальным именем (восстанавливается из БД) и заголовком `attachment`. |
| **Ограничение размера** | **1** | Файлы > 2МБ отклоняются. |
| **Интеграция с RBAC** | **1** | Загрузка и скачивание интегрированы с системой прав доступа (нельзя скачать чужой файл). |
| **Работа на сервере (Деплой)** | **2** | Приложение успешно развернуто на сервере (git pull), функционал работает удаленно. |
| **Итого** | **8** | |

### Штрафы

* **-2 балла:** Файл сохраняется с именем, которое прислал пользователь (`file.filename`). Это критическая уязвимость.
* **-1 балл:** Проверка типа файла только по расширению (`if file.filename.endswith(...)`).
* **-1 балл:** Файл читается в память целиком (`file.read()`) без контроля размера (потенциальный DoS).
